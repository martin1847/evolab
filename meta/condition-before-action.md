# 条件先于动作（condition-before-action）

> 给 agent 执行的指令：**判据必须在语法上先于（或焊进）祈使句；禁令必须自带作用对象。**
> 机制一句话：agent 逐句执行，祈使句就是动作触发点——排在它后面的判据永远到不了决策点。
> 有出处的锚：**guard clause（卫语句）**；同族：precondition / Design by Contract、
> 航空 QRH 应急清单的 IF–THEN 条件结构律。
> 来源：onboarding 活体门一日两抓同族反向病（2026-07-30 沉淀）。

## 机制：绑定失败，不是看不见

整篇文档都在上下文里，agent 物理上"看得见"后置的判据。败点在生成动作的那一刻：
执行循环里的 agent 读一步、发一个工具调用，一条干净的祈使句（"进 X settings"）是极强的
动作模板；后面那句限定条件在语法上是**游离的**——没有结构强迫模型把它和前面的动词绑定。
人类先建全文心智模型再动手，会自动回补这个绑定；agent 的绑定是概率性的。所以病名叫
**salience 反了**，不是信息缺失：信息在，权重错了。

这不是 LLM 怪癖。航空与医疗的 checklist 设计铁律就是条件先于动作——写
"IF engine fire THEN shut down"，绝不写 "Shut down engine.（若起火时）"。人在压力下执行
清单与 agent 在长上下文里执行步骤，是同一种逐句执行器。

## 两个病类（一日两例活体实证，同族反向）

- **V1 判据后置**：「做 Y。……X 时除外」——祈使句先触发，限定条件迟到。
  实证：接入文档"进项目 settings"祈使在前、层级判据孤悬两行外 → 已在用户级接线的机器被
  重复接线，同一封信冒泡两次。
- **V2 禁令无作用域**：「一条都不加」不写"一条**什么**"——无对象的禁令按模式匹配外溢到
  agent 手中的全部邻接任务。实证：修 V1 时的新措辞未圈定对象 → 相邻的 guard 接线被连坐跳过。
- 同族反向：一个让该发生的被重复，一个让不该拦的被拦。静态审查（包括异构冷评审）两轮
  都没看出原文病——此类措辞的行为影响**只有活体门抓得住**。

## 判别：按句不按篇

文档几乎都是散文与指令的混合体，按文档分类不可判。判据一句话：**这句话被读到的当口，
会不会触发一个动作（工具调用 / 配置写入 / 派发）？** 会 = 程序句，受本律；
不会（背景、动机、评审时判断项）= 文章句，自由发挥。

## 载体阶梯（对齐 structure-not-discipline 的 L0→L2）

- **L2 脚本化**：能代码化的决策整段脚本化，散文段消灭——实证：接入落点的层级决策表
  进 `agentmail wire` 一条命令，两个病类从机制上无处发生。
- **L1 带电清单行（句法 + 门）**：必须留在散文里的执行句统一
  `- [ ] <条件> → <动作>（对象：X）`，无条件写 `ALWAYS →`——条件位在语法上先于动词，
  形态半边可 lint（带 `→` 的步骤行条件位为空 = 红）。屋内名「**带电清单行**」：人可读、
  机可 lint 的窄语法，散文与脚本之间的半电层；有出处的锚 = controlled natural language
  （ASD-STE100 同族）+ executable checklist。
- **L0 写作自检两问**：判据并进祈使句了吗？禁令圈定作用对象了吗？——并标记此类改动
  **待活体门复验**（写作纪律降发生率，活体门兜底，两层不互相替代）。

## 为什么显性化

"agent 是逐句执行器"这个事实藏在隐式里，就会以新面孔反复坑每一个写指令的人：
文档人读全通顺、冷评审全绿、活体一跑就炸。显性化 = 把它从个人直觉升格为可传授的判据 +
可 lint 的句法 + 可脚本化的消灭路径——本质上，是**给散文写卫语句**。
