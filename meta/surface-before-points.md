# 先数面，再治点（surface-before-points）

> 给编排者与实现者的范式：对枚举出的点做治理（修复 / 清点 / 逐项处置）之前，先枚举**点所在
> 的面**（通道 / 入口 / 平面 / 消费机制），并证明这份面清单本身完备——视角转换 + 已知成员校准。
> 同族：measure-before-more（改前先量）、condition-before-action（动作前先给条件）——三条同一
> 骨架：**动作之前，先钉死决定动作正确性的那个上位对象**（量 / 条件 / 面）。

## 机制：清单从产生它的视角继承盲区

清单不是中立的：它从某个视角（工件目录、grep 词、已知病例）被生产出来，凡该视角照不到的
通道天然不进账。之后的治理再彻底，也只是"把看得见的点全治了"——盲区不是漏治，是**从未在
账上**。病征识别：同构问题在不同平面反复出现、每次都"补一个点"；复盘写成"下次记得查 X"
而不是"为什么 X 当时不在清单里"。

## 判据（fire 点已下沉，正源各归其位）

- **换视角复推**：这份清单从哪个视角产生？换到**消费者 / 运行时机制**视角重推一遍，
  未进账的通道即缺口。
- **已知成员校准**：清单也是一条检测链——消费其「完备」前先过 known-positive 校准；规则
  正源在 `skills/cto-orchestration/references/implementation-discipline.md` §否定性结论与
  Goodhart，本篇不复述其判据与动作，只指认它在面清单上的适用位。
- fire 点：goal-review 时刻 = `skills/cto-orchestration/references/review-dispatch.md`
  仪器六问第 6 问；修复时刻 = `skills/cto-orchestration/SKILL.md` §3「病类确认后枚举同模式点」
  ——那条管**面内**点的收敛，本篇管**面本身**的完备，两层缺一都会把盲区带进生产。

## 来源

外部席位三例同构盲区（配置平面漏项 / 治理点穷举漏面 / 整个消费面未进账）——共性是清单从
工件出发而非消费机制出发，"面没数完就治点"；≥3 例同向过样本门后收编（2026-08-06）。
