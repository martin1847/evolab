# 盘点仪式操作手册（stocktake）<!-- trunk:盘点仪式 -->

> SKILL §5「盘点仪式」的展开 = checklist 本体，逐条勾。触发词：盘点 / 接下来做什么 /
> 规划下一批 / stocktake——听到即走本 checklist，不即兴。与复盘的分工：复盘向后看
> （记账/教训，周期尾），盘点向前看（候选→取舍→提案，随叫随跑）；刚复盘过则跳过第 1 步
> 已扫过的源，只补增量。选题取舍判据单源在此，复盘与决策队列引用不复制。

## 四步 checklist

1. **扫源（Identify）**：候选不许凭记忆，逐源机械扫——台账敞口行 · LESSONS 无门/n≥2 行 ·
   DECISION_QUEUE 活跃项 · 停牌信件（攒例中的）· owner 当场新增。各仓具体源路径由该仓
   AGENTS.md 声明，本仪式只列源类型。扫不到的源标 `UNKNOWN`，不默认为空。
2. **标面定档（Prioritize）**：每候选一行，固定格式
   `[面 · Impact · Effort] + 一句价值判语 + 证据强度（n 计数 / [实测|读码|推断]）`——
   面与配比判据同 SKILL §2 配比轴（业务/工程面判「谁受益」，范式正源 leverage-line 篇）；
   配比失衡时真路径类候选自动置顶。
   判语写「谁受益、缺口多大」，不写实现方案。
3. **收口成提案**：top 3-5 排序 + 推荐首选（含一句为什么是它），**必须带不做/停牌名单**
   ——超出 5 项的全部落停牌行不展开，显式 Don't-do 防盘点变铺大饼。
4. **只提案不动工**：盘点产出 = owner 的裁决面；批了才进 goal 合同流程（大批次仍先过
   方案预审）。默认对话内呈现，owner 点名留档才落文件——盘点是决策辅助，不产衍生物。
