# 实现与验证纪律（按需加载）

仅在写实现 goal、诊断 ReOpen、设计验证或收工核证时读取。主干判据见 `../SKILL.md` §3；这里保存操作展开与常见失败模式。

## 行为变更

- 默认把实验、性能优化和未批准的新行为藏在 env flag 后，默认 OFF。
- ReOpen 已明确批准的修复可以默认 ON，但在 goal 写明理由与兼容边界。
- 不为普通 bugfix 机械加 flag；按项目既有兼容策略判断。

## Measure before more

修 bug 前依次证明：

1. bug 在当前基线与真实输入上可复现；
2. 观测值确实受怀疑机制约束，而非查错数据源、日志串、session 或部署版本；
3. 执行真实到达怀疑代码；读代码只产生候选，日志、trace 或失败探针才证明路径。

绑定约束未证时，先派观测与复测，不发投机修复。第一刀后重新测量；修复会改变下一轮的绑定约束。

高不确定方向准备进入昂贵设计/实现时，先完成最便宜的只读证伪，再在 goal 写一行实际 probe 与读数；preflight 门由 runtime 强制拒发——它只证明证据声明存在，不替代对读数真实性的独立核证（豁免类别的判据归 SKILL §1）。

## 门禁验证深度分档

门禁类改动的验证深度按**这道门误判的最坏后果**分档，不按改动大小——一律拉满会把成本吃在
无产出项上（外部席位双向实证：DENY 侧三次都是自证环节抓出门自身的洞、读代码看不出；
WARN 侧逐字节回归一段零发现，真救场的是三态矩阵的离线态阳性对照）：

| 门的严重度 | 必做自证 | 免做 |
|---|---|---|
| DENY 类（阻断 push/合并/CI） | 三态矩阵（红/绿/ERROR）· 既有关**逐字节**回归（stdout/stderr/rc 全等）· 新旧实现双盲对照 · 全量门自检 | — |
| WARN 类（只提醒不阻断） | 三态矩阵 · 既有关跑绿即可 · 全量门自检 | 逐字节回归 · 双盲对照 |

不可降三条（无论档位）：①量具先自证判别力（SKILL §3）；②红样本钉不可变锚（SHA 或仓内
fixture）；③声称「不阻断/不误伤」的红线必须实跑，不能只写文案。
自举盲区：门检查不了「自己有没有被跑过」，靠更外层兜（服务端 required check / 合并动作
拦截）——**但外层自身先验两件事再信**：①对**这条 ref** 真 required（读 ruleset API，如
`gh api repos/O/R/rules/branches/<ref>`；旧 `branches/<b>/protection` 对 ruleset 会 404、
`.protected` 只报「有无任一保护」、分不出是否含你的 required check，都不可作证据）；
②本次的绿产生于门**落地之后**（比该 required check 的 `completed_at` 与门合入时间；旧绿要
逼一次新 head 重跑——门已进 base 用 `update-branch`，base 未动则空 commit push；strict 只
强制齐平 base，不能当新鲜度证明）。两个失败态都不报错、只静默变绿（外部席位 n=2 实证：ruleset
include 漏路径 → 门红照样自合；门落地前的旧绿计数）。同族条目见 agent-backend selfcheck-gates「门的适用性纪律」。

## 病类收敛

枚举出的同模式点逐一标成安全 / 有嫌疑 / 需实验，一轮处理（规则本体见 SKILL §3「病类确认后枚举同模式点」）。

## 否定性结论与 Goodhart

只有决策依赖“未观察到 X”时才触发 known-positive 校准：先证明同一检测链能看见一个已知存在的 X；否则结论保持 `UNKNOWN`。验证动作数量不是验证有效性，坏验证会把不知道伪装成知道。

## 验证边界

- stub 掉被测函数只证明 stub（规则本体「不 mock 正在验证的边界」在 SKILL §3）。
- mock、打桩、stream smoke 与结构测试只能证明其覆盖范围，不证明真实部署路径。
- 本地绕过真 LLM、真队列、真数据库或真身份时，明确列入“未验证”，并安排部署后补验。
- 交付固定写清：验证了什么 / 没验证什么 / 剩余风险。

## 结构化数据

- JSON 等结构化数据的生成与解析不走 shell 拼接 / sed 正则——引号与转义必漏（实证 ×2 同日：
  printf 拼 JSON 遇含引号的 glob 产坏帧；sed 前缀贪婪匹配被嵌套重复键静默）。python 已在
  依赖里：`json.dumps` / `json.load` 是正路。

## 编辑新鲜度

rebase、另一 agent 写入同一 worktree、或任何会改目标文件的命令之后，重新读取再编辑。不要用旧上下文覆盖新文件；护栏提示 stale edit 时先重读，不绕过。
